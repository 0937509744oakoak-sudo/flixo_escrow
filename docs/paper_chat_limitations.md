# Limitations & Threats to Validity

*(½ หน้า — ก็อปเข้า Discussion / Limitations ของเปเปอร์ได้)*

งานนี้ประเมินระบบ hybrid (regex → LLM) สำหรับตรวจจับข้อความชักชวนซื้อขายนอกแพลตฟอร์มในแชท C2C ภาษาไทย โดยแยกผล Mock กับ Live อย่างชัดเจน ข้อจำกัดหลักมีดังนี้

**ขอบเขตข้อมูลและตัวอย่าง** ชุดหลักมีเพียง N=100 (สมดุล risky/safe) และชุดขยายรวม N=120 โดย +20 เป็น stress set ที่ออกแบบเจาะช่องโหว่จาก failure analysis ไม่ใช่สุ่มจากประชากรจริง ดังนั้น Accuracy 97% (N=100) กับ 89% (N=120) หรือ 50% (slice +20) ต้องอ่านคนละความหมาย และยังไม่สามารถสรุปไปยังผู้ใช้จริงทั้งแพลตฟอร์มได้ ข้อความส่วนใหญ่เป็นเคสสังเคราะห์/กึ่งจริงในโดเมน FLIXO ไม่ใช่ corpus สาธารณะขนาดใหญ่

**ภัยคุกคามภายใน (internal validity)** ข้อผิดพลาดที่เหลือส่วนใหญ่เกิดจาก cascade gate: เมื่อ regex ได้คะแนน 0 ระบบไม่เรียก LLM และเมื่อเรียกแล้วการรวมผลแบบ `max(regex, ai)` ทำให้ LLM ลด false positive ของ keyword กว้าง (เช่น “ผ่านแอป”) ไม่ได้ ดังนั้นตัวเลขประสิทธิภาพสะท้อนทั้งตัวจับคู่คำและนโยบาย escalate/merge ไม่ใช่ความสามารถของ LLM อย่างเดียว การประเมินยังไม่มีคอลัมน์ regex-only baseline แยกเต็มรูปแบบในตารางหลัก

**ภัยคุกคามภายนอก (external validity)** ผลจำกัดกับภาษาไทยและบริบท escrow/C2C รูปแบบการหลีกเลี่ยง (เช่น Line ID เว้นวรรคแปลก, คำพ้อง “โอนเงินนอก”) อาจต่างจากตลาดอื่นหรือภาษาอื่น Live latency พึ่งพาผู้ให้บริการ (Groq/OpenRouter) ซึ่งผันแปรตามเวลาและโควตา

**สิ่งที่งานนี้ไม่เคลม** ไม่ได้เสนอโมเดล AI ใหม่ ไม่เคลมความแม่นยำ 100% และไม่ใช้ผล eKYC / Slip / Dispute ที่ยังพึ่ง mock หรือตัวอย่างน้อยเป็นหลักฐานหลักของข้อสรุป การเปรียบเทียบ Mock กับ Live บนชุดเดียวกันแสดงว่า classification ตรงกัน — ความเสี่ยงหลักจึงไม่ใช่ “ตัวเลขจำลองหลอก” แต่เป็น coverage ของกฎและการออกแบบ pipeline

**ทิศทางถัดไป** ขยายข้อมูลจริงแบบมีแผนสุ่ม (ไม่ใช่เฉพาะ stress), เพิ่ม soft trigger ให้ LLM เห็นเคส score=0 ที่น่าสงสัย, ปรับ keyword/merge เพื่อลด FP polysemy, และรายงานต้นทุนต่อข้อความควบคู่ latency
